# Capture-ready technical package

Read DEMO_BIBLE.md first. This is an asset package, not a completed competition
film. Editing master: **1920×1080, 30 fps, 5400 frames maximum (180 seconds)**.
The edit map is `manifests/edit-plan.csv`; exact source cue timecodes are in
`manifests/source-clips.csv`. See `VALIDATION.md` for delivered coverage; all intervals are end-exclusive,
non-drop-frame 30 fps timecode. It totals 5400 frames. Planned edit slots are not
claims that missing owner footage exists. Short source clips require intercuts,
actual owner footage, readable still holds or diagram holds; do not stretch
2.48 seconds of WRECK aftermath into a false slow-response claim.

## Assets and provenance

- `captures/`: six H.264/yuv420p, 1920×1080, constant 30 fps MP4 sources. Silent.
  Each contains the actual paper assembly, normal input-driven win and ticket.
  DODGE clips finish on the actual Chaos Report. Exact durations, frame counts,
  source hashes, output SHA-256, world recipes, wins, ffprobe metadata and
  frame-indexed scene markers are in `manifests/capture.json`.
- `graphics/`: two editable native 1920×1080 SVGs generated by
  `tools/graphics.py`. They explain source behavior; they are not screen captures
  or evidence that public live inference exists. Import SVG into your editor, or
  rasterize once at 1920×1080 if the editor does not accept it.
- Existing stills: `../screenshots/mobile-menu.png`, `game-1.png`, `game-2.png`,
  `game-3.png`, `chaos-report.png`. These are prior actual public-release browser
  screenshots, not live Meta footage. Retain their portrait aspect ratio.
- `manifests/public-source-match.json` compares public and local gameplay source
  hashes. The dedicated harness serves these unchanged repository sources with
  a narrowly documented in-memory capture instrument. Nothing is uploaded.

Every generated clip is visibly labelled **ACTUAL OFFLINE FIXTURE GAMEPLAY ·
LOCAL CAPTURE**. The character is the existing default illustration, with the
HOT ROD fixture's role and tuning; it is not a generated hot-rod image, owner
photo or SAM cutout. Do not remove the distinction between these clips and the
owner's private live proof when editing. No fake responses or inference UI.

## Reproduce captures

Requirements: Node 22.9+, Playwright, Chromium with system libraries, ffmpeg and
ffprobe on PATH. Use an existing installed Playwright, or install it in a separate
tooling directory; no production dependency changes are needed. Example:

```bash
PLAYWRIGHT_MODULE=/absolute/path/to/node_modules/playwright \
  node docs/demo/tools/capture.cjs
python3 docs/demo/tools/graphics.py
# Optional: rasterize missing PNGs once with tools/render-graphics.cjs.
python3 docs/demo/tools/validate.py
```

The harness serves only allowlisted files on an ephemeral **127.0.0.1** port and
aborts external/API requests. It selects HOT ROD through the fixture control,
uses `?seed=7821`, offsets session two through the menu remix control, and
clicks the existing remix control on each round.
It captures a 390×844 iframe framed in a separate 1920×1080 editorial shell,
preserving the full arcade instead of stretching/cropping the canvas. Scrolls
between round tickets and report use the real DOM. Labels are editorial overlays
outside the game iframe, never fabricated game UI.

Local-only instrumentation exposes JSON snapshots and advances the existing
`update(1/30); draw()` functions. It replaces only the game's RAF scheduling in
memory; it writes no game files, changes no mechanics, sets no scores, forces no
results and performs no paid calls. Buttons and pointer inputs reach the original
handlers. WRECK drags/releases; BEAM taps within the actual catch window; DODGE
steers away from approaching hazards using observed positions. Wins are asserted.
A fixed simulation clock produces reproducible gameplay; OS fonts, Chrome builds,
CSS transitions and encoders can vary pixels/bitstreams. This is automated offline
test capture, not real-time human phone play. Preserve that provenance.

One pass writes each clip. Existing files are reused, never automatically rendered
again. Move an unwanted capture aside for an explicit targeted rerun; inspect the
manifest and failed step before rerunning. Do not repeatedly render the film.
The tool does not record Web Audio. Add only the existing approved DaemonV12 OST
from `public/audio/` in the editor; no replacement soundtrack. For genuine in-game
sound effects use owner recordings. Do not claim the silent MP4 contains them.

## Import the owner's Android footage

1. Record on the real Android device at its native resolution and 30/60 fps.
   Include explicit consent, actual Muse result, separate SAM action, real
   cutout in play, and successful native share. Keep 2 seconds before/after each
   action; record object + phone separately. Never record keys, accounts, headers,
   private URLs or notification previews. Owner controls all live calls.
2. Transfer original MP4 by USB/file transfer into a local folder. Do not use a
   messaging app that recompresses it. Review privately before importing.
3. Run `python3 docs/demo/tools/import-android.py /path/original.mp4 live-muse-sam.mp4`.
   This copies bytes to `android/`, hashes and probes the original; no transcoding,
   uploads or metadata sanitization. Original footage stays ignored by Git.
   Owner must review the adjacent JSON checklist; unchecked fields are pending.
4. In Resolve/Premiere/Kdenlive create a **1920×1080, 30 fps** timeline before
   importing media. Import `captures/*.mp4`, SVGs (or one-time PNG exports), approved
   OST and reviewed `android/*.mp4`. Preserve original Android frame rate and audio
   in the media bin; let the 30 fps timeline resample 60 fps footage at normal speed.
   For variable-frame-rate recordings, inspect sync first and transcode only the
   affected original once to a 30 fps constant-rate editing copy, keeping original
   and its hash. Do not silently reinterpret 60 fps as 30 fps slow motion.
5. Fit the whole portrait frame into 1080-high picture; use unused side space for
   captions. Never crop consent, the game hitboxes, result or share proof. Badge
   owner clips **PRIVATE LIVE META MODEL API**. Badge browser clips **OFFLINE DEMO**.
   Redact private information on an editing copy and inspect the exported frames.

## Source-accurate graphics / editorial checks

Muse: `meta_adapter.js` → photo interpretation → validated GamePlan in
`gameplan.js`. SAM: `sam_adapter.js` → mask path + bounds → browser compositing in
`game.js`; it is a separate opt-in, not a Muse-generated transparent bitmap.
GamePlan carries object/role/dialogue/bounded tuning, not arbitrary executable
code. `stage_machine.js` derives tags/seeds and allowlisted compatible recipes;
`game.js` paints existing modules, with a 1.4-second normal-motion assembly.
Remixes do not request a model or create new minigames. Chaos Report is a local
Canvas PNG with actual score and played-world names. No backend leaderboard.

Use the 00:20–00:36 and report/share slots only with genuine owner footage;
**they remain missing until supplied**. The optional daily roadmap teaser is
omitted in favor of working proof. Closing credits: Meta Muse Spark 1.3, Meta
SAM 3.1, original DaemonV12 OST, original hackathon game / Canvas / Stage Machine.

AI demonstration separate. Human preview, half-size legibility, audio sync,
